# 446h: header SPEC conformance against docs/header/engineering.md

## Objective

Map every requirement in `docs/header/engineering.md` (exported surface,
invariants, error semantics, configuration, persistence, test strategy,
observability) to the code that meets it and a test that fails if it breaks.
Where no test exists, add one; where the code does not meet the requirement,
fix it with a test. Design or API changes are reported, not made.

## Slices

1. This plan.
2. Package-internal rules in `internal/header/engconformance_test.go`: both
   header copies, checksum, scan order, unknown-field round trip, repair of
   the primary from the secondary.
3. Public surface in `pkg/luks2/headerengconformance_test.go`: the
   `*Volume`/`*Header` accessors and error semantics the table marks missing.
4. Accuracy fixes to `docs/header/engineering.md` where the document and the
   code disagree and the code is right.

## Out of scope

- CLI rows (`cli.md`), already audited.
- Header bounds and ranges, api.md surfaces and the exported
  unsupported-requirement error, covered by the open draft for this issue.
- Any API or design change; such items go in the report.
