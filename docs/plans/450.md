# 450: SPEC conformance, the downstream seam

## Objective

Release criteria for the downstream seam: the APIs consumers use
(`Volume.Enroll`, `Volume.UnlockWithProvider`, `keyprovider.NewFIDO2`,
`keyprovider.FromToken`, `keyprovider.NewCommand`) behave as the SPEC says,
and conformance tests in `pkg/luks2/seam_test.go` prove it.

## Slices

1. Seam conformance tests (`pkg/luks2/seam_test.go`): enroll and unlock
   through each provider kind the seam offers. Done.
2. A FIDO2 provider rebuilt from a header token keeps the token's
   keyslots. `FromToken` built the provider's token from the FIDO2
   parameters alone, so `p.Token().Keyslots` was empty and
   `UnlockWithProvider` refused with "the provider's token names no
   keyslot".
   - Test first: `pkg/keyprovider` round trip, the token's `Keyslots`
     survive `FromToken` into `p.Token().Keyslots`, and a later change to
     the source slice does not reach the provider.
   - Test: `NewCommand` with `WithToken` keeps the token's keyslots.
   - Seam test: enroll with a fake FIDO2 helper, read the token from the
     header, `FromToken`, `UnlockWithProvider` succeeds with no wrapper.
   - Fix: `FromToken` (pkg/keyprovider/fido2.go) copies the source
     token's keyslots onto the provider's token. No exported API change.

## Out of scope

- Any new exported function, option or field.
- Changes to `.github/`, `docs/SPEC.md`, `ROADMAP.md`.
- Integration targets that need Docker (CI runs them).
