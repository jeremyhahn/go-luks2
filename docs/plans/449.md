# Plan: SPEC conformance, CLI rows

## Objective

Every row of the feature `docs/*/cli.md` documents (command, flag, exit
status, refusal) maps to the code that implements it and to a test that fails
if it breaks. A row without a test gets one, built on the `internal/cli`
fakes (no root). A wrong doc is fixed in the doc; wrong code is fixed with a
test. A fix that needs a design or API change is reported, not made.

## Slices, in order

Earlier slices (on this branch already):

1. volumes, keyslots, recovery-keys: create limits, symlink refusal, addkey
   `--slot`, killslot, recovery format/token/output/recovery-file rows.
2. wipe, filesystems, tokens: wipe and mount refusals, header-only erase,
   token export/exists/remove, info null entries.
3. header `restore` rows, dm-crypt exit statuses, loop-devices `create`.

Final slice:

4. `docs/fips/cli.md`: in a FIPS-mode child process, `create` with no KDF
   options writes PBKDF2-SHA512; `open` and `testkey` of an Argon2-only
   volume fail with `ErrFIPSImportRequired` (no activation, no "opens");
   `isluks`, `keyslots` and `header show` still read it.
5. `docs/loop-devices/cli.md`: `open` and `close` rows.
6. `isluks`: exit statuses, `--luks2`, `--verbose`.
7. `docs/dm-crypt-activation/cli.md`, `docs/kernel-keyring/cli.md`: the rows
   other than exit statuses.
8. `docs/header/cli.md`: the rows other than `restore`.

Each slice adds tests to `internal/cli/conformance_test.go` (or the
command's own test file) for the rows found without one.

## Out of scope

- Library (`pkg/`) rows, audited by the other conformance rows.
- New CLI verbs or flags (for example a `MigrateToFIPS` verb).
- `docs/SPEC.md`, `ROADMAP.md` and `.github/`.
