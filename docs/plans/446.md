# 446: SPEC conformance, header

## Objective

Every normative requirement in the header feature docs, and the token and
cryptsetup-interop rows that rest on the header, is backed by code and by a
unit test that fails if the requirement breaks. Where a requirement has no
test, add one beside the existing tests; where the code does not meet it, fix
the code with a test. A fix that needs a design change is listed in the
report, not made.

## Slices

1. Header bounds and ranges: hostile JSON nesting depth; token id range 0-31
   for `SetToken` and `RemoveToken`; token keyslot references past 31 and
   negative; `Tokens` lists only slots 0-31; keyslot ids above 31 are never
   tried. Tests in `internal/header` and `pkg/luks2`.
2. `api.md` surfaces: `docs/header/api.md` names the `Header` accessors and
   errors, `docs/tokens/api.md` names every token and keyprovider export;
   absent FIDO2 flags and a never-run helper's exit code
   (`pkg/keyprovider`).
3. Callers can read an unsupported requirement from `luks2.Error` (this
   slice). `docs/header/architecture.md` said unlock, activation and every
   header write refuse a container with an unsupported mandatory requirement
   with an error naming it, but the typed error lives only in
   `internal/header`, and a write returned it as `ErrIO` with no Detail. No
   alias is exported: the API baseline deletes `UnsupportedRequirementError`
   in favour of `luks2.Error{Op, Path, Kind, Detail, Err}`. Instead every
   such refusal is a `*luks2.Error` whose `Kind` is
   `ErrUnsupportedRequirement` and whose `Detail` names the requirement and
   the mandatory set. Test added:
   `TestUnsupportedRequirementIsReadableFromLuks2Error` (package
   `luks2_test`; `Unlock`, `AddKeyslot`, `ChangeKeyslot` and
   `RemoveKeyslot` on an `inline-hw-tags` volume: `errors.As` to
   `*luks2.Error`, the Kind, Detail naming the requirement,
   `errors.Is(err, luks2.ErrUnsupportedRequirement)`). Docs:
   architecture.md and api.md say the caller matches `luks2.Error` and its
   Kind/Detail, not a named type; CHANGELOG "Unreleased" gains a Fixed
   entry.

## Out of scope

- A change to the requirement check itself, or support for any mandatory
  requirement, `inline-hw-tags` included.
- Packages outside `pkg/luks2`, `pkg/keyprovider` and `internal/header`.
- Any change to CI, `docs/SPEC.md` or `ROADMAP.md`.
- Design or API changes beyond the alias: listed in the slice report.
