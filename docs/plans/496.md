# 496: code-review.yml template v5.12.6, the gate never waits for a twin

## Objective

The `Code Review (codex)` gate no longer holds a hosted runner while another
run's `Codex review` queues for the one codex runner. It reads the queued and
in-progress runs of the same PR, base and head once; an APPROVED head passes
as before, and otherwise a twin whose `Codex review` job is queued or in
progress fails the gate at once, naming that run (its own gate posts the
head's newest check). API errors still fail closed. The gate's timeout drops
from 80 to 10 minutes.

Every go-luks2 CUSTOMIZE block stays, the twin selector included: a run of
this PR, base and head matches with its run-name alone or with the request
kind (`(review: ...)` or `(re-review: ...)`), never the template's
`.display_title == $t`.

## Round 2 status (review round 1, one P1)

The attempt check listed every run on the head, an active twin included,
and counted its unfinished job a failed attempt, so it failed before the
twin branch: an approved head with a twin reviewing failed, an unapproved
one got the failed-attempt message. Fix (gate job only; jq_runs and
jq_attempt unchanged): the twin read keeps every active twin's run ID in
`$twins`, and check_attempts passes over those runs before ranking.
Completed attempts rank as before: a failed latest one on the head or a
carried-from head fails with the failed-attempt message, twin or not. An
unfinished run on a carried-from head is no twin of this head and still
fails closed as a failed attempt.

Tests: every twin fixture is listed in the unfiltered run listing too (as
GitHub lists it), so the twin cases exercise check_attempts; new cases: a
failed attempt plus a twin (approved, unapproved), a twin on a head whose
approval was carried (passes), a twin plus a failed attempt on the
carried-from head, an unfinished run on the carried-from head.
