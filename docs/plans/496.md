# 496: code-review.yml template v5.12.6, the gate never waits for a twin

## Objective

The `Code Review (codex)` gate no longer holds a hosted runner while another
run's `Codex review` queues for the one codex runner. It reads the queued and
in-progress runs of the same PR, base and head once; an APPROVED head passes
as before, and otherwise a twin whose `Codex review` job is queued or in
progress fails the gate at once, naming that run (its own gate posts the
head's newest check). API errors still fail closed. The gate's timeout drops
from 80 to 10 minutes.

Every go-luks2 CUSTOMIZE block stays, the twin selector included: a run of
this PR, base and head matches with its run-name alone or with the request
kind (`(review: ...)` or `(re-review: ...)`), never the template's
`.display_title == $t`.

## Slices (one PR)

1. `.github/workflows/code-review.yml`: the template's v5.12.5 -> v5.12.6
   change, CUSTOMIZE blocks kept (the branch's first commit).
2. Tests, `test/ci/workflows/codereview_test.go`:
   - `TestGateRefusesARetargetedPullRequest` anchors the live base check
     after the twin read, not after the removed wait.
   - The fake `curl` serves fixtured queued/in-progress run lists (or a
     failing list) and logs every request; the gate harness puts a `sleep`
     on PATH that fails the run.
   - `TestGateNeverWaitsForATwinReview`: version line v5.12.6, gate
     `timeout-minutes: 10`, no sleep and no loop in the twin read, the
     go-luks2 twin selector kept, the fail-at-once branch after the verdict;
     then table cases run the gate script: no twin (approved, none, changes
     requested), a queued or in-progress twin of either kind or of no kind
     fails at once naming it, an approved head passes with a twin running,
     the first twin is named, an ended review, this run itself, another base,
     another PR or another suffix is no twin, an unreadable listing or
     unreadable twin jobs fail closed; each run lists each status once.
