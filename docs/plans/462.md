# 462: SPEC conformance, filesystems and cryptsetup-interop engineering.md

## Objective

Audit `docs/filesystems/engineering.md` and
`docs/cryptsetup-interop/engineering.md` requirement by requirement. For each
requirement, name the code (file:func) and a unit test that fails if it
breaks. Where the test is missing, add one beside the existing tests, using
`t.TempDir` files and the package's fakes only (no root, no real device).
Where only an integration or interop target can prove a requirement, name
that target and add nothing. Fix code that does not meet a requirement, with
a test; list fixes that need a design or API change instead of making them.

## Slices

1. Filesystems (`pkg/filesystem`): exported surface, tools table and
   invariants. Tests added in `pkg/filesystem/*_test.go` for requirements
   without one (for example the `CommandError` text and unwrap, the reserved
   `Info` fields `Inspect` leaves empty). Commit:
   `test(filesystems): SPEC conformance, engineering.md`.
2. cryptsetup interop: each requirement of the interop engineering doc mapped
   to code and to a unit test in `pkg/luks2` or `internal/*`, or to the
   interop target that proves it. Missing unit tests added beside the
   existing ones. Commit: `test(interop): SPEC conformance, engineering.md`.

Doc text is corrected only where it is inaccurate against the code.

## Out of scope

- The CLI rows (`cli.md`), audited already.
- Interop and integration targets (need root, devices or cryptsetup); named
  in the report, not run here.
- Design or API changes; listed in the report.
- `.github/`, `docs/SPEC.md`, `ROADMAP.md`.
