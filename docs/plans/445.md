# Plan: SPEC conformance, volumes and recovery-keys (#445)

## Objective

Every normative requirement in the volumes and recovery-keys feature docs is
backed by code and by a unit test that fails if the requirement breaks. Where
a requirement has no test, add one beside the existing tests; where the code
does not meet it, fix the code with a test. A fix that needs a design or API
change is listed in the report, not made.

## Slices, in order

1. `docs/volumes/api.md` and `docs/recovery-keys/api.md`: ErrClosed and
   ErrReadOnly on every method, the api.md surface, the CSPRNG source of
   recovery keys.
2. `docs/volumes/` SPEC rows: rootless exec-free core import closure, shared
   lock for Unlock and exclusive lock for every write method, key custody for
   AddKeyslot/ChangeKeyslot/MigrateToFIPS handles, no process state on import,
   the core closure does not log.
3. `docs/keyslots/`: unbound UnlockKeyslot, digest cancellation, data area
   untouched, removal from every digest and token, non-contiguous slots,
   32 fresh random salt bytes.
4. `docs/recovery-keys/`: renderings match the format table.
5. `docs/volumes/engineering.md` section by section, and
   `docs/recovery-keys/engineering.md` errors and persistence (this slice).
   Tests added: no lock held between calls on an open handle, and the
   further gaps the section audit finds.

## Out of scope

- Packages outside `pkg/luks2` and its `internal/` helpers (dm-crypt,
  loop, filesystem): their own feature docs and lanes.
- Any change to CI, `docs/SPEC.md` or `ROADMAP.md`.
- Design or API changes: listed in the slice report instead.
